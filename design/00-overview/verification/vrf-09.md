doc_id: VRF-09
unchecked: ไม่ได้ทดสอบกรณีธุรกรรมล้มหลังออกเลขที่เอกสาร (ว่าเลขที่ไม่ถูกใช้ซ้ำ) เพราะหาวิธีทำให้ล้มหลังออกเลขผ่าน API ไม่ได้; ไม่ได้ทดสอบหน้าจอ (ไม่มี E2E); ไม่ได้ทดสอบเส้นทางล็อกอินด้วย SSO จริง (โปรไฟล์ทดสอบใช้ token ที่เซ็นด้วยคีย์ร่วม) และไม่ได้ทดสอบหลาย instance ของ API หลัง proxy; ไม่ได้วัดประสิทธิภาพ (NFR-01); ผู้เขียนเอกสาร ผู้เขียนโค้ด และผู้เขียนทดสอบเป็น AI ตัวเดียวกัน ไม่ใช่ทีมพัฒนาอิสระ; การตัดสินใจที่เติมลงเอกสารรอบนี้ (404 นอกขอบเขต ปัดครึ่งขึ้น เขตเวลา Asia/Bangkok ลบแถวอนุมัติเมื่อปฏิเสธ ความแม่นยำของเงิน) ยังไม่ได้ยืนยันกับเจ้าของโจทย์

# รายการตรวจ 9

ชุดทดสอบ API ด้วย Playwright เขียนจากเอกสารที่ส่งต่อ แล้วรันกับ stack ตาม ADR-01 บนเครื่อง (ASP.NET Core 8, SQL Server 2022, Redis, nginx) ผ่านทั้ง 80 ข้อ: เกณฑ์ตรวจรับครบทั้ง {{count:ac}} ข้อ (ข้อที่ตรวจผ่านฐานข้อมูลใช้ sqlcmd ตรง) กฎใน runtime view และ convention ที่เกณฑ์ไม่ครอบคลุม และการตรวจ response ทุกตัวกับ OpenAPI รวมคำขอพร้อมกัน 4 แบบบนฐานข้อมูลจริง ทดลองแก้โค้ดบน stack จริงให้ผิดสองแบบ (ขอบวงเงิน 20,000.00 และข้ามการแยกหน้าที่) ทดสอบจับได้ทั้งสองแบบ (ก่อนหน้านี้บน server แบบหน่วยความจำทดลองสี่แบบ จับได้ครบ)
