unchecked: ตาราง ข้อมูลที่บันทึก เขียนมือจากโค้ดอ้างอิงและ runtime view ตัวตรวจยืนยันว่าครบตาม schema และตรงกับ request แต่ไม่ได้ยืนยันว่าค่าที่ระบุตรงกับสิ่งที่โค้ดเขียนจริงทุกคอลัมน์ (ชุดทดสอบตรวจผลลัพธ์ที่สังเกตได้เท่านั้น); ไม่ได้ทดสอบกรณีธุรกรรมล้มหลังออกเลขที่เอกสาร (ว่าเลขที่ไม่ถูกใช้ซ้ำ) เพราะหาวิธีทำให้ล้มหลังออกเลขผ่าน API ไม่ได้; หน้าจอเขียนแบบไม่เน้นความสวยงาม จึงไม่ได้ตรวจเรื่องการเข้าถึงตาม UIR-05 (อัตราส่วนสี ลำดับแป้นพิมพ์) ไม่ได้ทดสอบหลายเบราว์เซอร์ มือถือ หรือหน้าจอขนาดอื่น และ SPA อ่านโทเค็นจาก localStorage ที่ฉีดโดยการทดสอบ ไม่ได้ลองเส้นทาง OIDC จริง; ไม่ได้ทดสอบเส้นทางล็อกอินด้วย SSO จริง (โปรไฟล์ทดสอบใช้ token ที่เซ็นด้วยคีย์ร่วม) และไม่ได้ทดสอบหลาย instance ของ API หลัง proxy; ไม่ได้วัดประสิทธิภาพ (NFR-01); ผู้เขียนเอกสาร ผู้เขียนโค้ด และผู้เขียนทดสอบเป็น AI ตัวเดียวกัน ไม่ใช่ทีมพัฒนาอิสระ; การตัดสินใจที่เติมลงเอกสารรอบนี้ (404 นอกขอบเขต ปัดครึ่งขึ้น เขตเวลา Asia/Bangkok ลบแถวอนุมัติเมื่อปฏิเสธ ความแม่นยำของเงิน) ยังไม่ได้ยืนยันกับเจ้าของโจทย์

# รายการตรวจ 9

ชุดทดสอบ API ด้วย Playwright เขียนจากเอกสารที่ส่งต่อ แล้วรันกับ stack ตาม ADR-01 บนเครื่อง (ASP.NET Core 8, SQL Server 2022, Redis, nginx) ผ่านทั้ง 113 ข้อ (API 82 ข้อ และเบราว์เซอร์ Chrome 31 ข้อ): เกณฑ์ตรวจรับครบทั้ง {{count:ac}} ข้อ (ข้อที่ตรวจผ่านฐานข้อมูลใช้ sqlcmd ตรง) กฎใน runtime view และ convention ที่เกณฑ์ไม่ครอบคลุม และการตรวจ response ทุกตัวกับ OpenAPI รวมคำขอพร้อมกัน 4 แบบบนฐานข้อมูลจริง ทดลองแก้โค้ดบน stack จริงให้ผิดสามแบบ (ขอบวงเงิน 20,000.00 ข้ามการแยกหน้าที่ใน API และหน้าจอไม่ซ่อนปุ่มอนุมัติของตนเอง) ทดสอบจับได้ทุกแบบ (ก่อนหน้านี้บน server แบบหน่วยความจำทดลองสี่แบบ จับได้ครบ)
