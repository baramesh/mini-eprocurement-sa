doc_id: FND-22
what: 'เมื่อทบทวนเอกสารหลังลองเขียนระบบสี่รอบ พบว่าเล่มสถาปัตยกรรมกับเล่มข้อกำหนด API พูดเรื่องเดียวกันซ้ำ (ขั้นตอนและกฎตรวจของ operation อยู่ทั้งในตาราง runtime view และย่อหน้ากฎตรวจของ operation) ทำให้แก้กฎต้องแก้สองที่; ตาราง request บอกแค่ปลายทางของฟิลด์ที่ client ส่ง ไม่บอกค่าที่เซิร์ฟเวอร์ใส่เอง (status เลขที่เอกสาร เวลา ผู้เรียก ผลคำนวณ) จึงไม่มีตารางเดียวที่บอกว่า operation เขียนคอลัมน์ไหนด้วยค่าอะไร; ชื่อมุมมองในเล่มสถาปัตยกรรมไม่มีกรอบรองรับและไม่ระบุผู้อ่าน'
fix: 'แยกหน้าที่: เล่มข้อกำหนด API เก็บวิธีเรียก request response ผลลัพธ์ทุกแบบ ที่มาของฟิลด์ และตัวอย่าง ส่วนขั้นตอนภายในและลำดับการตรวจอยู่ที่ runtime view แหล่งเดียว (ตัดย่อหน้ากฎตรวจที่ซ้ำ ใช้ช่อง Runtime view ชี้); เพิ่มตาราง ข้อมูลที่บันทึก ต่อ operation ที่เปลี่ยนข้อมูล ที่มาจากไฟล์เดียวและตัวตรวจเทียบกับ schema (คอลัมน์ NOT NULL ทุกตัวต้องมีที่มา ฟิลด์ใน request ทุกตัวต้องถูกเก็บหรือใช้) ทดสอบเชิงลบห้าแบบจับได้ครบ; เล่มสถาปัตยกรรมระบุมุมมองกับผู้อ่านตาม ISO/IEC/IEEE 42010 เทียบโครงกับ arc42 และ C4 และเพิ่มบทแนวคิดที่ใช้ร่วมทุก operation'
