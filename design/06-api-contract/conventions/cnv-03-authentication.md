# การยืนยันตัวตน

`Authorization: Bearer <JWT>` ออกโดย SSO; API อ่านตัวตนและบทบาทจาก claim ไม่รับจาก body

| claim | ความหมาย |
|---|---|
| `sub` | รหัสผู้ใช้ (`app_user.user_id`) ให้หน้าจอรู้ว่าตนเองคือใครเพื่อซ่อนปุ่มตาม BR-04; API ไม่เชื่อค่านี้ ใช้ `email` ค้นผู้ใช้ |
| `email` | ใช้ค้น `app_user.email` เพื่อได้รหัสผู้ใช้และหน่วยงาน; ไม่พบหรือ `is_active` เป็นเท็จตอบ `403` |
| `roles` | อาร์เรย์ของบทบาท (ค่าตาม `app_user.role_code`); ผู้ใช้ถือได้มากกว่าหนึ่งบทบาท และ API ตรวจสิทธิ์จาก claim นี้ |
| `aud` | ต้องเท่ากับ `eprocurement` |
| `exp` | เวลาหมดอายุ (วินาทีแบบ Unix); เลยแล้วตอบ `401` |

`app_user.role_code` คือบทบาทหลักตอนตั้งค่าผู้ใช้ ไม่ใช่ข้อจำกัดของ claim; กฎแยกหน้าที่ (BR-04) เทียบรหัสผู้ใช้ จึงบังคับได้แม้ผู้ใช้ถือทั้งบทบาทผู้ขอซื้อและผู้อนุมัติ ลายเซ็นและ public key ตามที่ตกลงกับ IdP ตอนเชื่อมต่อ; โปรไฟล์ทดสอบดูใน CNV-10
