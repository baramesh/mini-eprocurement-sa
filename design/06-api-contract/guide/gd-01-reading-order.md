# นักพัฒนาอ่านอะไร ที่ไหน

เอกสารชุดนี้แบ่งตามคำถามที่นักพัฒนาถาม แต่ละคำถามมีเล่มเดียวที่เป็นเจ้าของคำตอบ เล่มอื่นอ้างถึงไม่ซ้ำ เริ่มจากตารางนี้ แล้วดูตัวอย่างใน flow ถัดไป

<!-- table: คำถามของนักพัฒนากับเล่มที่ตอบ -->
| คำถาม | เล่มที่ตอบ | หัวข้อ | ใครใช้ |
|---|---|---|---|
| ระบบแตกเป็นหน่วยอะไร โค้ดแบ่งโมดูลอย่างไร รันบนเครื่องอย่างไร | การออกแบบสถาปัตยกรรมของระบบ | ภาพรวมสถาปัตยกรรม, การแบ่งโมดูลของ API, โครงสร้างโค้ด (รวมการสร้างและรันบนเครื่อง) | หลังบ้าน หน้าบ้าน |
| เรื่องที่ทุก operation ทำเหมือนกัน (สิทธิ์ idempotency เลขที่เอกสาร เวลาและเงิน) | การออกแบบสถาปัตยกรรมของระบบ | แนวคิดที่ใช้ร่วมทุก operation | ทุกคน |
| หน้าจอมีอะไร ใครเข้าได้ ไปหน้าไหนต่อ | การออกแบบ UX/UI | รายละเอียดหน้าจอ, ผังการนำทาง, wireframe | หน้าบ้าน |
| หน้าจอเรียก API อะไรเมื่อไร ส่งและอ่านฟิลด์ใด สถานะและข้อผิดพลาดแสดงอย่างไร | การออกแบบ UX/UI | พฤติกรรมของหน้าจอ (ตารางเหตุการณ์ ตารางผูกกับ API ตารางสถานะ) | หน้าบ้าน |
| กฎกลางของหน้าจอ (วันที่ เงิน สถานะ ข้อผิดพลาด การส่งซ้ำ เมนู) | การออกแบบ UX/UI | กฎกลางของหน้าจอ | หน้าบ้าน |
| operation เรียกอย่างไร ส่งอะไร ได้อะไรกลับ ผิดได้กี่แบบ | ข้อกำหนด REST API | ข้อกำหนดรายละเอียดของแต่ละ operation (ข้อมูลทั่วไป พารามิเตอร์ request response ตัวอย่าง) | หน้าบ้าน หลังบ้าน |
| ฟิลด์แต่ละตัวมาจากตารางไหน และ operation เขียนตารางไหนด้วยค่าอะไร | ข้อกำหนด REST API | คอลัมน์ "ที่มา" ของ response และ request, ตาราง "ข้อมูลที่บันทึก" | หลังบ้าน |
| operation ทำงานภายในอย่างไร ตรวจอะไรก่อนหลัง ผิดแล้วตอบอะไร | การออกแบบสถาปัตยกรรมของระบบ | มุมมองขณะทำงาน (ช่อง Runtime view ในตารางข้อมูลทั่วไปของ operation บอกว่าอ่านชิ้นไหน) | หลังบ้าน ผู้ทดสอบ |
| ตารางและคอลัมน์มีความหมายอย่างไร ข้อมูลตัวอย่าง | การออกแบบฐานข้อมูล และไฟล์ใน `sql/` | พจนานุกรมข้อมูล, `sql/schema.sql`, `sql/sample-data.sql` | หลังบ้าน |
| กฎธุรกิจและเกณฑ์ตรวจรับ | ข้อกำหนดความต้องการ และเกณฑ์ตรวจรับ | กฎธุรกิจ, เกณฑ์ตรวจรับรายข้อของแต่ละ operation | ทุกคน ผู้ทดสอบ |
| งานชิ้นนี้ต้องอ่านและทำอะไรบ้าง พร้อมเมื่อไร | แผนการดำเนินงาน และโฟลเดอร์ `plan/` | การ์ดงานแต่ละใบ (เกณฑ์ตรวจรับ ความสัมพันธ์ เกณฑ์พร้อมพัฒนา) | ทุกคน |

ลำดับที่แนะนำ: หลังบ้านอ่านแนวคิดที่ใช้ร่วมก่อน แล้วอ่านทีละ operation ตามการ์ด (สัญญา runtime view ตารางที่เกี่ยว กฎธุรกิจ) หน้าบ้านอ่านกฎกลางของหน้าจอก่อน แล้วอ่านทีละหน้าตามการ์ด (หน้าจอ พฤติกรรม สัญญาของ operation ที่หน้านั้นเรียก)
