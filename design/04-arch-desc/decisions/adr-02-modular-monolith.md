# โครงสร้าง API

**บริบท:** ขนาดโจทย์เล็ก ธุรกรรมหลายตารางต้อง commit พร้อมกัน (เช่น อนุมัติขั้นสุดท้ายเปลี่ยนทั้ง approval, PR และ audit)

**การตัดสินใจ:** ทำ API เป็น modular monolith ที่แยกโมดูลตามหน้าที่แต่ใช้ฐานข้อมูลเดียวและธุรกรรมเดียว

**ผลที่ตามมา:** ธุรกรรมง่ายและทดสอบง่าย ไม่ต้องจัดการข้อมูลสอดคล้องข้ามบริการ แยกเป็น microservices ภายหลังได้ยากขึ้นถ้าโมดูลอ้างตารางของกันโดยตรง จึงให้โมดูลคุยกันผ่านอินเทอร์เฟซ
