# บทนำและขอบเขต

เอกสารนี้อธิบายสถาปัตยกรรมของระบบจัดซื้อจัดจ้างขนาดย่อ: บริบท หน่วยประกอบ การแบ่งโมดูลของ API มุมมองขณะทำงาน การติดตั้ง ความมั่นคงปลอดภัย ความสัมพันธ์กับคุณลักษณะคุณภาพ และการตัดสินใจสำคัญ ทุกข้อเสนอเป็นร่างของ AI จากข้อกำหนดในเอกสารอื่น ผู้จัดทำต้องตรวจรับก่อนใช้ เทคโนโลยีที่เลือกสอดคล้องกับ schema ที่ออกแบบไว้ (SQL Server) ไม่ได้ผ่านการทดลองใช้งาน

## มุมมองที่ใช้และผู้อ่าน

โครงเล่มเทียบกับ arc42 (บริบท หน่วยประกอบ runtime การติดตั้ง แนวคิดที่ใช้ร่วม การตัดสินใจ คุณภาพ) และแผนภาพตามแบบ C4 (บริบท หน่วยประกอบ โมดูล) ส่วน runtime ใช้ sequence diagram มุมมองแต่ละตัวมีผู้อ่านและคำถามที่ตอบตามตาราง ตามกรอบ ISO/IEC/IEEE 42010

| มุมมอง | หัวข้อในเล่มนี้ | ผู้อ่าน | ตอบคำถาม |
|---|---|---|---|
| บริบทและหน่วยประกอบ | ภาพรวมสถาปัตยกรรม | ผู้ตัดสินใจ ทีมโครงสร้างพื้นฐาน | ระบบแตกเป็นหน่วยอะไร พูดกับใคร ผ่านอะไร |
| โมดูล | การแบ่งโมดูลของ API | นักพัฒนาหลังบ้าน | โค้ดแบ่งเป็นโมดูลอะไร โมดูลไหนเป็นเจ้าของ operation และตารางใด |
| Runtime | มุมมองขณะทำงาน | นักพัฒนาหลังบ้าน ผู้ทดสอบ | operation นี้ทำงานภายในอย่างไร ตรวจอะไรก่อนหลัง ผิดแล้วตอบอะไร เขียนตารางไหน |
| แนวคิดที่ใช้ร่วม | แนวคิดที่ใช้ร่วมทุก operation | นักพัฒนาทุกคน | เรื่องที่ทุก operation ต้องทำเหมือนกันมีอะไร และกติกาอยู่ที่ไหน |
| การพัฒนา | โครงสร้างโค้ดของ API service | นักพัฒนาหลังบ้าน | วางโค้ดและรันบนเครื่องอย่างไร |
| การติดตั้ง | การติดตั้ง | ทีมโครงสร้างพื้นฐาน | รันที่ไหน แยกสภาพแวดล้อมอย่างไร |
| ความมั่นคงปลอดภัย | ความมั่นคงปลอดภัย | ผู้ตรวจสอบ | ขอบเขตความเชื่อถือและมาตรการเทียบ OWASP |

ข้อมูลของ request และ response รวมที่มาของฟิลด์อยู่ที่เล่มข้อกำหนด API ไม่ซ้ำที่นี่ เล่มนี้เก็บขั้นตอนภายในของแต่ละ operation แหล่งเดียว
